# Shared Obsidian Note-Taking Reference

本文件是所有记笔记 skill 共用的 Obsidian 规范层。它只保存从用户资料中提炼出的、跨领域可复用的规则，不保存原始资料。未来新增记笔记 skill 时，应在其 `SKILL.md` 中引用本文件。

## 使用方式与优先级

- 所有明确要求“记笔记”“整理成笔记”或写入 Obsidian 的任务，都先遵循本 reference。
- 本 reference 负责通用的 Obsidian 组织、格式、链接、证据和质量规则。
- AI、SAP 或其他领域 skill 负责专业内容；用户明确提出的要求和长期偏好优先于各 skill 的默认写作建议。本文关于记忆技巧和内部链接的偏好适用于所有记笔记 skill。
- 先观察用户已有笔记、索引、文件夹和 Canvas，再决定格式与位置；不要为了统一而重写既有内容。

## 对话范围与默认完整性

- 当用户要求“记笔记”“整理成笔记”但没有指定范围时，默认把当前对话从开始到当前请求中的所有相关知识点都纳入整理范围，不得只记录最近一条消息或最后一节课程。
- 范围包括用户提供的课程原文、对话中的讲解与更正、补充说明、操作路径、代码、数据、截图中可复用的信息、已确认结论、限制和易错点。
- 如果对话包含多个主题或课程，只在主题能独立复用、且拆分确实便于查找时才分成多篇笔记。需要内部链接时，按下文的“内部链接从简”规则在正文相关位置添加；不要求每个主题都彼此互链。
- “全部内容”指全部有知识价值、可复用或能作为证据的内容，不要求逐字复制寒暄、重复措辞或无信息量的旁白；重复内容可以去重，但不得因去重遗漏新增事实、例子或更正。
- 写入前必须回顾当前对话并进行覆盖检查，确认此前各段内容已经记录；若用户明确指定某一方面、某一节课或排除范围，则以用户指定范围为准。

## 笔记目标

笔记应当便于未来复习、搜索和复用，优先保留：

- 可验证的核心知识与适用条件；
- 用户实际观察到的现象、操作、代码、实验和结果；
- 限制、易错点以及与既有知识的关系。

不要把笔记扩写成与任务无关的教材，也不要为了“完整”加入没有证据的背景或边界情况。

## 避免课程导读式概括

笔记直接记录可复用的概念、机制、对象关系、操作、证据和适用边界，不写课程介绍或教案式导读。不要使用 `学习目标`、`课程目标`、`总体关系`、`核心关系`、`本节概述`、`学习路线总览`、`学习成果`、`核心认识` 等泛化标题，也不要用近义标签重新包装同类概括；省略“完成本课后应能……”等课程目的和不增加具体事实的宽泛总结。如果标题只有“Overview/概述/总览/核心问题/核心作用/课程时间线/学习路线”等泛化标签、看不出具体知识对象，应改成该段实际说明的产品、机制、流程或操作；若内容只是课程目的、顺序或重复总结且没有独立可复用事实，则删除。像“业务流程概览”这类标题只有在正文确实解释该具体流程时才保留。

同理，不要把重复事实集中到“复习要点”“一句话总结”或“本章要点”一类通用标题下；有独立价值的内容改用具体主题标题，重复内容省略。

如果课程目标中包含有用知识，只保留知识本身，并放到以具体概念、产品、组件、对象或流程命名的标题下。需要说明关系时，写清楚各对象的职责或实际交互；保留具体关系事实，不保留“总体关系”等空泛框架。课程步骤、实验结果和来源证据只有在对复现或理解有用时才记录，不要按课程结构机械搭建笔记。

## 记忆口诀与复习技巧

- 默认不添加自创的记忆法、速记口诀、“可以这样记”段落、记忆提示或同类复习技巧；优先记录概念、条件、流程、证据和适用边界。
- 只有用户明确要求，或原始资料中的口诀本身是该知识点不可分割且实际有用的内容时，才保留，并标明其来源；不要为让笔记显得易记而重新编口诀。

## 证据边界

明确区分：

- 资料明确说明的内容；
- 用户实际观察或系统实测的内容；
- 整理者的推断或尚未验证的解释。

推断必须保留“可能”“推测”“需要验证”等不确定性。资料不足时使用 `[待确认]` 或领域 skill 指定的等价占位符。不得伪造引用、实验数字、版本行为、截图、链接或系统结果。

## 语言、元数据与 Markdown

- 默认以中文为主；保留专业术语、产品名、模型名、库名、API、CLI、代码标识符、版本号和必要的原文关键词。
- 保留 SAP 英文专业术语时，仅使用能在 SAP 官方日文本地化资料（如 SAP Help Portal、SAP 产品文档或官方课程资料）中确认、且符合对应产品和语境的日语术语；不得根据英文自行猜译或套用一般词典译法。无法确认官方日语术语时保留英文，不添加猜测性日译。确认后，在每篇笔记首次出现的重要术语后标注日语，例如 `company code（会社コード）`；保留英文原文段落时也只标注可确认的关键术语，不需要逐句翻译普通英文。后续重复词通常不必重复标注，除非换了语境或容易混淆。
- 不翻译或改写代码、字段名、API/CLI 标识符、产品名等精确标识；需要解释时，在其后的说明中补充日语专业词汇。必须保持逐字准确的引用时不要改动引文，在引文紧邻处补充术语对照。
- 新增 YAML、标签、标题和文件名时，遵循同目录已有风格。
- 如果新建标签且标签值包含空格，将空格改为短横线；不要擅自重写既有标签。
- 重要代码、命令、配置和公式分别使用正确的代码块或 LaTeX；公式应解释符号、形状、单位或取值范围。
- 只有在确实改善理解时才使用表格、图示或 callout。

## Obsidian 文件模型

- Vault 是一个自包含的文件夹；笔记、图片、PDF、Canvas 和配置都属于其中的普通文件。不要把一个 Vault 嵌套到另一个 Vault 中。
- 笔记通常是 `.md` Markdown 文件；一篇笔记只属于一个文件夹，标签和链接用于表达可以跨文件夹的关系。
- 文件夹和文件按文本顺序排序。若采用数字前缀，应使用零填充（例如 `01`、`02`、`10`），避免 `10` 排在 `2` 前面。

## 链接、别名与反向链接

- 内部链接使用 `[[笔记名]]`，外部链接使用 `[显示文字](https://example.com)`。
- `[[目标笔记|显示文字]]` 只改变这一处链接的显示文本；需要全局生效的替代名称时，在 YAML 中使用 `aliases` 属性。
- 指向不存在的内部链接会显示为未创建的笔记入口；只有在确实有意创建待办入口时才保留，不要积累大量悬空链接。
- Backlinks 会根据其他笔记中的内部链接自动生成，不能直接编辑；未链接提及只有在关系明确时才转换为正式链接。

### 内部链接从简

- 默认不添加笔记之间的内部 Wiki Link；先让当前笔记自包含。只有读者必须打开另一篇笔记，才能理解、验证或完成当前知识点中的具体内容时，才添加最少的直达链接。
- “可供回顾”“延伸阅读”“相关主题”或仅因主题相近、同属一个领域而建立的链接通常不需要；一般导航交给已有索引或 Canvas。
- 必要的链接直接放在说明具体依赖的位置；若不链接也能理解、验证和使用当前笔记，就省略。
- 不创建“相关信息”“相关主题”“相关笔记”“延伸阅读”“文件地图”“来源地图”等独立章节来罗列内部链接，也不在笔记末尾追加一组 Wiki Link。
- 来源文件名可在顶部资料来源属性中简洁说明；只有用户要求来源清单，或复现/审计工作确实依赖逐项追溯时，才在正文保留详细文件清单。
- `## 外部参考` 可按“外部参考”规则保留实际使用且有价值的网页、文档、论文或仓库链接；不要把内部 Wiki Link 混放在该节。

## YAML Properties、标签、搜索与 Bases

- YAML front matter 必须位于笔记最顶部，并用 `---` 包围；键名区分大小写。
- 可使用 `aliases`、`tags`、日期、状态或项目等 properties 支持检索和 Bases。包含特殊字符的值应加引号；包含 Wiki Link 的值也应加引号，例如 `pair: "[[相关笔记]]"`。
- 标签不包含空格；新增标签默认使用小写、短横线或嵌套路径（例如 `#project/work`），保持命名一致，避免过度打标签。
- 搜索已有笔记时可使用精确短语、`file:`、`path:`、`tag:`、`[property]`、`[property:value]`、`OR` 和 `-` 排除条件；需要时再启用大小写匹配。
- 如果 Vault 使用 Bases，`.base` 文件以笔记文件为行、以 properties 为列；修改 properties 时要考虑现有 Base 的筛选、排序和视图。

## Markdown、Callout、表格与模板

- Obsidian 的基本 Markdown 包括标题、粗体、斜体、高亮、删除线、列表、任务清单、代码块和水平线。列表前留一个空行；普通单换行可直接作为换行，不要依赖行末空格。
- Callout 使用 `> [!type] 标题`，内容行以 `>` 开头；在类型后加 `-` 或 `+` 可分别设置默认折叠或展开。
- 表格使用管道符和分隔行；在分隔行中使用冒号控制左对齐、居中或右对齐。只有表格能改善比较或检索时才使用。
- 模板是可复用的笔记骨架。使用模板前确认模板文件夹路径与实际目录完全一致；模板中的 `{{date}}`、`{{time}}` 和 `{{title}}` 等占位符在插入时解析。

## Canvas 与导航文件的稳定性

- Canvas 保存为 `.canvas` 文件，并通过文件路径引用笔记、图片或其他卡片内容；移动或改名被引用的笔记可能造成卡片失效。
- 因此，任何创建、合并、改名或移动笔记的操作都要核对 Canvas、索引、Wiki Link 和章节锚点，必要时同步更新入口。

## 结构与目录

- 根据内容选择概念、操作、问题排查、实验、论文或其他合适结构，不强行套用固定模板。
- “注意点”“易错点”和补充内容应放在所属主题附近；必要时使用 Obsidian callout。
- 当笔记包含多个有意义的一级或二级章节时，在 YAML 后添加目录，并在修改标题时同步检查目录、编号和锚点。
- 不要留下空的“外部参考”或其他辅助章节。

## 既有笔记、位置与命名

写入前先按文件名、标题、关键词、技术对象和主题搜索相关笔记：

1. 有合适笔记或标题时，补充已有内容并避免重复；
2. 多篇相关笔记时，选择一篇作为主要归档位置；不要求补充关系链接，只有当前笔记缺少读者必须查看的具体细节时，才添加最少的直达链接；
3. 没有相关笔记时，根据索引、Canvas、文件夹和相邻笔记确定新位置；无法确定时标记 `[待确认]`，不要臆造目录。

### 重复内容处理

即将写入的内容如果与已有笔记中的内容重复或等价，应直接在原有笔记、原有条目或对应标题下面补充本次新增的信息；完全相同的内容无需再次写入，也不要另建重复条目或笔记。只有确实存在新的事实、证据、例子或更正时，才记录差异部分。

不要覆盖无关文件、擅自重组文件夹或改写用户原有内容。新文件名应包含可搜索的主题关键词，并遵循现有命名方式。

## Wiki Link、索引与 Canvas

- 默认不添加笔记间 `[[Wiki Link]]`。只有在读者必须跳转到另一篇笔记才能理解、验证或执行当前内容时才使用最少的链接，并确认目标文件名真实存在；不要为了关系、导航或图谱完整而加链。
- 如果库使用索引笔记或 Canvas，创建、更新、合并或改名后核对入口、文件名、Wiki Link、章节标题、锚点和层级关系。
- 找不到对应 Canvas 或索引时报告 `[待确认]`；不要因为存在空白 Canvas 就自动创建或重排整个导航。
- 仅用户明确要求修正 Canvas 时，才进行布局、节点或箭头修改；正常记笔记时只做必要的入口同步。

## 图片、截图与敏感信息

- 实际图片、截图、图表或错误证据可访问，且图片比清晰的文字、公式或表格更能表达结构、趋势、空间关系、界面位置或证据时，才复制到主题约定的 `Assets` 文件夹，并用稳定文件名和 Obsidian embed 插入；不强行贴图。
- 图片不可访问时才使用 `[图片：...]` 占位符；不得伪造图片、使用临时路径或不稳定外链。
- 每张嵌入图片附近必须有可检索的文字解读，说明关键对象、箭头、坐标、颜色、层级、界面区域或版式的含义，以及图片如何支持该知识点、操作判断或结论；不能只贴图而省略解释。
- 对密钥、个人数据、内部地址和其他敏感信息进行脱敏，绝不把秘密写入笔记。

## 外部参考

- 只保留实际使用且有复用价值的外部链接，优先链接到官方文档、论文原文、官方仓库或直接页面。
- 外部结论与用户个人观察分开表达，不把外部说明写成用户系统已验证的结果。
- 没有可保留的外部链接时，省略 `## 外部参考`，不要留下空标题。

## 完成前检查

- 内容可复用、可搜索，且没有不必要的重复；
- 事实、观察和推断边界清楚；
- 标题、目录、YAML、代码、公式、图片和链接有效；
- 笔记位于合理目录，未覆盖无关内容；
- Canvas/索引存在时已核对，无法确认的部分已标记；
- 没有写入秘密、隐私数据、临时路径或未经证实的结论。

## 同步维护

- `.codex/skills/_shared/obsidian-note-taking-reference.md`
- `00 Agent skills/skills/_shared/obsidian-note-taking-reference.md`

两份文件的正文应保持一致。
